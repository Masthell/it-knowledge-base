# **ТЕОРИЯ: АРХИТЕКТУРА КЛАСТЕРА 1С ПРЕДПРИЯТИЕ**

**Кластер 1С** — это группа серверов, работающих вместе для обслуживания информационных баз.

### **Зачем нужна кластерная архитектура?**
1. **Масштабируемость** — можно добавлять серверы при росте нагрузки
2. **Отказоустойчивость** — если один сервер упал, другие продолжают работать
3. **Балансировка нагрузки** — пользователи распределяются между серверами
4. **Упрощение управления** — централизованное управление всеми серверами

### **Компоненты кластера:**
```
┌─────────────────────────────────────────┐
│           Кластер 1С                    │
├─────────────────────────────────────────┤
│  Рабочие серверы      Менеджер кластера │
│  ┌─────┐ ┌─────┐          ┌──────┐     │
│  │ WS1 │ │ WS2 │          │ CM   │     │
│  └─────┘ └─────┘          └──────┘     │
│   1541     2541             1541        │
└─────────────────────────────────────────┘
         ↓            ↓            ↓
    Пользователи   Пользователи  Администратор
```

### **2. ФАЙЛЫ КЛАСТЕРА И УПРАВЛЕНИЕ КЭШЕМ**

### **Структура файлов кластера:**
```
C:\ProgramData\1C\1cv8\
├───<Имя_кластера>_<Порт>\
│   ├───1Cv8Log\           # Логи
│   ├───1Cv8Clst\          # Данные кластера
│   │   ├───1Cv8.lst       # Основной список
│   │   ├───1Cv8.dt        # Данные
│   │   └───1Cv8.tat       # Таблицы
│   ├───Reg1541\           # Регистрация (порт 1541)
│   └───RIPH1541\          # Кэш
```

### **Ключевые файлы:**
- **`1Cv8.lst`** — список рабочих серверов
- **`1Cv8.dt`** — данные о сессиях, блокировках
- **`1Cv8.tat`** — табличные данные

### **Управление кэшем:**
**Кэш кластера** хранит:
1. **Метаданные** информационных баз
2. **Сессионные данные** пользователей
3. **Блокировки** объектов

**Параметры кэша:**
```ini
# В файле ragent.conf
[cluster]
memory_limit = 1024          # Лимит памяти в МБ
lifetime_limit = 3600        # Время жизни в секундах
```

**Очистка кэша:**
```powershell
# Остановить службы 1С
Stop-Service "1C:Enterprise 8.3 Server"
Stop-Service "1C:Enterprise 8.3 Server Agent"

# Удалить кэш
Remove-Item "C:\ProgramData\1C\1cv8\*\RIPH*" -Recurse -Force

# Запустить службы
Start-Service "1C:Enterprise 8.3 Server Agent"
Start-Service "1C:Enterprise 8.3 Server"
```

### **3. СИСТЕМА ПОРТОВ 1С (1540-1591)**

### **Базовые порты:**
- **1540** — **ragent** (Агент сервера) — управление кластером
- **1541** — **rmngr** (Менеджер кластера) — основной порт для подключения
- **1560-1591** — рабочие процессы

### **Как работает нумерация:**
```
Сервер 1:         Сервер 2:         Сервер 3:
1540 - ragent     2540 - ragent     3540 - ragent
1541 - rmngr      2541 - rmngr      3541 - rmngr  
1560-1591 - WS    2560-2591 - WS    3560-3591 - WS
```

**Правило:** **+1000 к номеру порта для каждого нового сервера**

### **Полная таблица портов:**
| Порт | Назначение                          | Протокол |
|------|-------------------------------------|----------|
| 1540 | Центральный агент сервера (ragent)  | TCP      |
| 1541 | Центральный менеджер (rmngr)        | TCP      |
| 1545 | Резервный порт агента               | TCP      |
| 1546 | Резервный порт менеджера            | TCP      |
| 1560-1591 | Рабочие процессы (rphost)      | TCP      |
| +1000 | Следующий сервер в кластере         |          |

---

### **4. ПРИНЦИП РАБОТЫ КЛАСТЕРА**

### **Процесс подключения пользователя:**
1. **Пользователь** → Подключается к `server:1541` (менеджер кластера)
2. **Менеджер кластера** → Находит свободный рабочий процесс (например, 1560)
3. **Рабочий процесс** → Подключается к SQL Server
4. **Пользователь** → Работает через порт 1560

### **Пример с 3 серверами:**
```yaml
Кластер "Основной":
  Сервер 1 (192.168.1.10):
    - ragent: 1540
    - rmngr: 1541
    - rphost: 1560-1563
  
  Сервер 2 (192.168.1.11):
    - ragent: 2540
    - rmngr: 2541  
    - rphost: 2560-2563
  
  Сервер 3 (192.168.1.12):
    - ragent: 3540
    - rmngr: 3541
    - rphost: 3560-3563
```

### **5. КОНФИГУРАЦИОННЫЕ ФАЙЛЫ**

### **ragent.conf (основной файл конфигурации):**
```ini
[General]
ClusterPort=1540
MainPort=1541
SecurityLevel=2
Period=6000
AllowRemoteAdmin=1

[Cluster]
MainServer=192.168.1.10:1541
MemoryLimit=1024
LifetimeLimit=3600

[WorkerProcess]
MinMemLimit=128
MaxMemLimit=512
```
**Расположение:** `C:\Program Files\1cv8\conf\ragent.conf`

### **Запуск вручную:**
```cmd
# Запуск агента
ragent.exe -port 1540 -regport 1541 -range 1560:1591

# Запуск рабочего процесса  
rphost.exe -port 1560 -range 1560:1591
```

### **6. ПРАКТИЧЕСКОЕ ПРИМЕНЕНИЕ**

### **Сценарий 1: Добавление второго сервера в кластер**
1. Установить 1С на второй сервер
2. Запустить с портами +1000:
   ```
   ragent -port 2540 -regport 2541 -range 2560:2591
   ```
3. В консоли администрирования добавить сервер в кластер

### **Сценарий 2: Настройка балансировки нагрузки**
```ini
# В конфигурации кластера
[LoadBalancing]
Enabled=1
MaxSessionsPerProcess=50
Timeout=300
```

### **Сценарий 3: Мониторинг портов**
```powershell
# Проверить какие порты слушает 1С
netstat -ano | findstr ":15"

# Результат:
# TCP    0.0.0.0:1540       0.0.0.0:0       LISTENING       4520  # ragent
# TCP    0.0.0.0:1541       0.0.0.0:0       LISTENING       4520  # rmngr  
# TCP    0.0.0.0:1560       0.0.0.0:0       LISTENING       5612  # rphost
```

### **7. ТИПИЧНЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ**

### **Проблема: "Порт уже занят"**
```powershell
# Найти процесс, занимающий порт
netstat -ano | findstr ":1540"

# Убить процесс (если не 1С)
taskkill /PID <PID> /F

# Или поменять порт в ragent.conf
ClusterPort=1640
MainPort=1641
```

### **Проблема: "Не удается подключиться к кластеру"**
```powershell
# Проверить брандмауэр
netsh advfirewall firewall show rule name=all | findstr "1540|1541"

# Добавить правило
netsh advfirewall firewall add rule name="1C Ports" dir=in action=allow protocol=TCP localport=1540-1591
```

### **Проблема: "Кэш переполнен"**
```powershell
# Очистить кэш через службы
Restart-Service "1C:Enterprise 8.3 Server"

# Или вручную
ragent.exe -clear cache
```
