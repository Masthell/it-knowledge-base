## Теория и базовые концепции

**Управление доступом (IAM)** — это фундамент безопасности ОС. Оно определяет, кто (Субъект) может делать что (Действие) с чем (Объект). Главная цель — предотвратить **НСД** (несанкционированный доступ) и обеспечить подотчетность действий.

> **💡 Ключевое правило:** 
> **Принцип наименьших привилегий (PoLP)** — пользователь или процесс должен иметь ровно столько прав, сколько необходимо для выполнения конкретной задачи, и ни битом больше.


| Понятие                                   | Суть                                                                                                                                     | Контекст                                                        |
| :---------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------- |
| **Управление доступом**                   | Совокупность правил, определяющих, какие действия субъекты (пользователи, процессы) могут выполнять над объектами (файлы, папки, порты). | Основа информационной безопасности.                             |
| **DAC (Discretionary Access Control)**    | Дискреционное управление доступом — владелец объекта самостоятельно решает, кому и какие права предоставить.                             | Гибкое, но уязвимое для неконтролируемого распространения прав. |
| **MAC (Mandatory Access Control)**        | Мандатное управление доступом — доступ определяется системой на основе меток безопасности. Владелец не может изменить права.             | Высокозащищённые среды (госструктуры, военные).                 |
| **RBAC (Role-Based Access Control)**      | Ролевое управление доступом — права назначаются ролям, пользователи получают права через назначение на роль.                             | Корпоративный сектор, Active Directory.                         |
| **ABAC (Attribute-Based Access Control)** | Атрибутное управление доступом — решение о доступе принимается динамически на основе атрибутов пользователя, ресурса, окружения.         | Основа Zero Trust.                                              |
| **ACL (Access Control List)**             | Список управления доступом — механизм реализации DAC, где для каждого объекта хранится список субъектов и их прав.                       | NTFS-права в Windows, POSIX ACL в Linux.                        |
| **Принцип наименьших привилегий (PoLP)**  | Пользователь или процесс должны иметь ровно столько прав, сколько необходимо для выполнения задачи.                                      | Фундаментальный принцип защиты.                                 |
| **IAM (Identity & Access Management)**    | Комплексный подход к управлению идентификацией, аутентификацией, авторизацией и аудитом.                                                 | Современные системы управления доступом.                        |
| **НСД (Несанкционированный доступ)**      | Доступ к информации или ресурсам в нарушение установленных правил.                                                                       | Часто происходит через избыточные или забытые права.            |

## Архитектура и главные компоненты

Система контроля доступа строится на базе одной или нескольких моделей.

### 1. Модели управления доступом
*   **DAC (Discretionary) — Дискреционное:** Владелец файла сам решает, кому дать доступ (NTFS в Windows, `chmod` в Linux). Гибко, но небезопасно — пользователь может случайно расшарить лишнее.
*   **MAC (Mandatory) — Мандатное:** Система решает всё на основе меток секретности. Владелец не может изменить права. Применяется в госсекторе и армии (SELinux, Astra Linux).
*   **RBAC (Role-Based) — Ролевое:** Права дают не человеку, а роли (Бухгалтер, Админ). Пользователь входит в группу и получает её права. Это стандарт для бизнеса (Active Directory).
*   **ABAC (Attribute-Based) — Атрибутное:** Доступ зависит от условий (время, IP-адрес, отдел). Основа концепции **Zero Trust**.

### 2. Аудит событий (Windows Event ID)
Аудит позволяет расследовать инциденты после того, как они произошли.
*   **4624:** Успешный вход в систему.
*   **4625:** Ошибка входа (индикатор брутфорса).
*   **4720:** Создание новой учетной записи.
*   **1102:** Очистка журнала безопасности (признак того, что хакер "заметает следы").

#### Глубокое погружение: Windows MIC (Integrity Control)
В Windows есть уровни целостности: **Low** (браузеры), **Medium** (юзер), **High** (админ). Даже если вы админ, программа с уровнем Low не сможет записать файлы в системную папку без вашего явного подтверждения.

## Практика и настройка в реальной жизни

В реальной инфраструктуре 80% угроз — внутренние (инсайдеры). Защита строится на комбинации IAM и мониторинга.

**Сравнительная таблица моделей доступа:**

| Модель | Кто управляет | Безопасность | Где применяется |
| :--- | :--- | :--- | :--- |
| **DAC** | Владелец объекта | Низкая | Обычные ПК, файлы |
| **MAC** | Администратор/Система | Максимальная | Спецслужбы, гостайна |
| **RBAC** | Администратор (группы) | Высокая | Корпоративные сети (AD) |

## Основные инструменты и утилиты

Команды и службы для управления правами:

- `chmod` / `chown` — (Linux) изменение прав и владельца файла.
- `secpol.msc` — (Windows) локальная политика безопасности и настройка аудита.
- `icacls` — (Windows) управление ACL (списками доступа) через консоль.
- `auditd` — (Linux) мощная служба для глубокого аудита действий пользователей.
- **PAM (Privileged Access Management)** — класс систем для контроля действий администраторов (запись сессий, выдача прав "на время").

**Пример команды проверки прав в Linux:**
```bash
# Просмотр прав (rwx) и владельца
ls -l /etc/shadow
# Изменение владельца файла
sudo chown root:shadow /etc/shadow
```

## Траблшутинг 

**Где искать причины отказов в доступе?**
- Windows: `Event Viewer` -> `Security Log`.
- Linux: `/var/log/auth.log` или `ausearch -m avc` (если включен SELinux).

**Типовые проблемы и их решения:**

1. **Проблема: Пользователя добавили в группу AD, но доступа к папке всё равно нет.**
   - **Причина:** Токен доступа обновляется только при входе в систему.
   - **Решение:** Пользователю нужно выполнить **Logoff / Logon** (выйти и зайти снова).

2. **Проблема: Ошибка "Access Denied" у администратора при доступе к папке пользователя.**
   - **Причина:** В DAC-модели даже админ может быть не вписан в ACL.
   - **Решение:** Стать владельцем объекта (Take Ownership) через расширенные настройки безопасности, а затем добавить себя в список доступа.

3. **Проблема: SELinux блокирует работу веб-сервера, хотя права 777 стоят.**
   - **Причина:** Несоответствие меток контекста безопасности (MAC).
   - **Решение:** Проверить через `ls -Z` и поправить контекст командой `restorecon`.

## Вопросы

**Вопрос 1: В чем главное отличие DAC от MAC?**
> **Краткий ответ:** В DAC владелец файла сам решает, кому дать доступ. В MAC права диктует система (администратор) через метки, и владелец ничего не может изменить.

**Вопрос 2: Что такое "Принцип наименьших привилегий"?**
> **Краткий ответ:** Это выдача минимально необходимого набора прав для выполнения задачи. 
> **Пример:** Если сотруднику нужно только читать отчеты, у него не должно быть прав на их удаление или редактирование.

**Вопрос 3: Зачем нужен аудит событий 4625?**
> **Ответ:** Это событие неудачного входа. Если в журнале их тысячи за минуту — значит, идет атака методом перебора паролей (Brute-force).
