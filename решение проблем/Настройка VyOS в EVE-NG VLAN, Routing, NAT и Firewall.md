## Теория и базовые концепции

**VyOS** — это сетевая операционная система с открытым исходным кодом на базе Debian. Она превращает обычный сервер или виртуальную машину в мощный маршрутизатор корпоративного уровня. В среде **EVE-NG** VyOS часто используется как центральный шлюз для всей лаборатории.

> **💡 Ключевое правило:** 
> В VyOS любая настройка проходит два этапа: `commit` (применить изменения в оперативную память) и `save` (сохранить в конфигурационный файл). Если не сделать `save`, после перезагрузки настройки пропадут.

---

### Архитектура и главные компоненты
Маршрутизатор VyOS объединяет в себе несколько ролей:

1. **L3 Gateway (SVI):** С помощью механизма **vif (Virtual Interface)** один физический порт превращается в Trunk, принимающий тегированный трафик (802.1Q). Каждый vif выступает шлюзом для своего VLAN.
2. **DHCP Server:** Автоматически раздает IP-адреса, маски и DNS клиентам в разных подсетях.
3. **Stateful Firewall:** Фильтрует трафик не просто по портам, а отслеживает состояние соединений (`established`, `related`).
4. **NAT (Masquerade):** Позволяет устройствам из внутренних сетей (VLAN 10/20) выходить в интернет через один внешний IP-адрес маршрутизатора.

#### Глубокое погружение: VLAN и Интерфейсы
- **VIF (Virtual Interface):** Это логический интерфейс. Например, `eth0 vif 10` — это интерфейс для VLAN 10 на физическом порту eth0.
- **Inter-VLAN Routing:** По умолчанию VyOS маршрутизирует трафик между всеми своими интерфейсами. Чтобы изолировать гостевую сеть от основной, нужно использовать Firewall.

## Практика и настройка в реальной жизни

В лаборатории EVE-NG мы эмулируем типичную офисную сеть: основная зона и гостевая зона (Wi-Fi), которые должны быть изолированы.

**Типовой конфиг интерфейсов и DHCP:**
```bash
# Настройка VLAN 10 (Основная)
set interfaces ethernet eth0 vif 10 address 192.168.10.1/24
set service dhcp-server shared-network-name LAN_10 subnet 192.168.10.0/24 default-router 192.168.10.1

# Настройка VLAN 20 (Гостевая)
set interfaces ethernet eth0 vif 20 address 192.168.20.1/24
set service dhcp-server shared-network-name GUEST_20 subnet 192.168.20.0/24 default-router 192.168.20.1
```

**Настройка NAT (выход в интернет):**
```bash
# eth1 — смотрит в сторону провайдера/облака EVE-NG
set nat source rule 100 outbound-interface eth1
set nat source rule 100 source address 192.168.0.0/16
set nat source rule 100 translation address masquerade
```

## Основные инструменты и утилиты

Шпаргалка по командам VyOS:

- `configure` — переход в режим редактирования настроек.
- `show interfaces` — просмотр статуса всех портов и IP-адресов.
- `monitor traffic interface eth0` — встроенный аналог tcpdump для захвата пакетов "на лету".
- `show dhcp server leases` — список выданных IP-адресов клиентам.
- `commit` — применение настроек.
- `save` — сохранение настроек в `/config/config.boot`.

**Пример ограничения доступа (Firewall):**
[Запрещаем гостевой сети VLAN 20 доступ к основной VLAN 10]
```bash
set firewall name GUEST_TO_LAN default-action drop
set firewall name GUEST_TO_LAN rule 10 action accept
set firewall name GUEST_TO_LAN rule 10 state established related
set interfaces ethernet eth0 vif 20 firewall in name GUEST_TO_LAN
```

## Траблшутинг 

**Типовые проблемы и их решения:**

1. **Проблема: Клиенты в VLAN не получают IP-адреса.**
   - **Причина:** В EVE-NG порт коммутатора, подключенный к клиенту, не настроен как Access-порт в нужном VLAN.
   - **Решение:** Проверить настройки Cloud/Switch в EVE-NG. Убедиться, что на VyOS поднят соответствующий `vif`.

2. **Проблема: Есть интернет с самого роутера, но нет у клиентов.**
   - **Причина:** Забыли настроить NAT (masquerade) или не включена маршрутизация.
   - **Решение:** Проверить `show nat source rules`. Убедиться, что у клиентов шлюзом (Default Gateway) указан IP-адрес VyOS.

3. **Проблема: После перезагрузки роутера все настройки сбросились.**
   - **Причина:** Использовали только `commit`, но не сделали `save`.
   - **Решение:** Всегда вводите `save` после успешного тестирования изменений.

## Вопросы 

**Вопрос 1: Что такое VIF в контексте VyOS?**
> **Краткий ответ:** Это виртуальный подуровневый интерфейс (Virtual Interface), привязанный к конкретному VLAN ID на физическом порту. Аналог "sub-interface" в Cisco.

**Вопрос 2: Зачем в правилах Firewall указывать `state established related`?**
> **Краткий ответ:** Чтобы разрешить ответный трафик. 
> **Детали:** Если клиент инициировал запрос (например, DNS), сервер должен иметь возможность ответить. Это правило позволяет проходить только тем пакетам, которые являются частью уже открытых сессий.

**Вопрос 3: В чем разница между командами `commit` и `save`?**
> **Ответ:** `commit` активирует настройки прямо сейчас (в ОЗУ), но они исчезнут после ребута. `save` записывает текущую активную конфигурацию на диск для постоянного хранения.
