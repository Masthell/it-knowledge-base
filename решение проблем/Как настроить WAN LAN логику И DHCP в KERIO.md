## 1. Как настроить WAN/LAN логику И DHCP в KERIO

Kerio Control — межсетевой экран/маршрутизатор для малого и среднего бизнеса.

### **Быстрая настройка WAN/LAN:**

#### **Шаг 1: Подключение интерфейсов**
```
Физические порты:
- ETH0 (WAN) → Интернет провайдер (DHCP или статический IP)
- ETH1 (LAN) → Внутренняя сеть (например, 192.168.1.1/24)
```

**Конфигурация в веб-интерфейсе:**
```ini
# WAN интерфейс (внешний)
Interface: ETH0
Type: External
IP: DHCP клиент (или статический от провайдера)
Gateway: auto

# LAN интерфейс (внутренний)
Interface: ETH1  
Type: Internal
IP: 192.168.1.1
Mask: 255.255.255.0
DHCP Server: Enabled
```

#### **Шаг 2: Настройка DHCP сервера**

**Вкладка "DHCP Server":**
```yaml
Общие настройки:
- Включить DHCP: 
- Пул адресов: 192.168.1.100 - 192.168.1.200
- Маска: 255.255.255.0
- Шлюз: 192.168.1.1 (сам Kerio)
- DNS: 192.168.1.1 (или 8.8.8.8)

Резервирование адресов (опционально):
- MAC: 00:1A:2B:3C:4D:5E → IP: 192.168.1.50
- MAC: AA:BB:CC:DD:EE:FF → IP: 192.168.1.51
```

**Пример CLI команды (если доступен):**
```bash
# Настройка DHCP пула
dhcp server pool add name="LAN_Pool" \
  start="192.168.1.100" \
  end="192.168.1.200" \
  mask="255.255.255.0" \
  gateway="192.168.1.1" \
  dns="192.168.1.1, 8.8.8.8"
```

#### **Шаг 3: Настройка NAT и правил**

**NAT (Преобразование адресов):**
```yaml
Автоматически создается правило:
Source: LAN (192.168.1.0/24)
Destination: WAN
Action: Masquerade (динамический NAT)
```

**Базовые правила firewall:**
```yaml
Правила по умолчанию:
1. LAN → WAN: Разрешить всё
2. WAN → LAN: Запретить всё (кроме разрешенного)
3. LAN → LAN: Разрешить всё
```

### **Проверка работы:**
```cmd
# Подключите компьютер к LAN порту
# Проверьте получение IP
ipconfig /all
# Должно быть: IP из диапазона 192.168.1.100-200
# Шлюз: 192.168.1.1
# DNS: 192.168.1.1

# Проверьте интернет
ping 8.8.8.8
```

### **2. VPN, QoS, фильтрация контента**

### **2.1 VPN (Virtual Private Network)**

#### **Типы VPN в Kerio:**

**A. Site-to-Site VPN (Офис-Офис)**
```yaml
Настройка туннеля между двумя Kerio:
- Тип: IPsec
- Локальная сеть: 192.168.1.0/24 (Офис 1)
- Удаленная сеть: 192.168.2.0/24 (Офис 2)
- Pre-shared key: сложный_пароль_123!
- Шифрование: AES-256
```

**B. Remote Access VPN (Удаленные сотрудники)**
```yaml
1. SSL VPN (Kerio VPN Client):
   - Порт: 443 (HTTPS)
   - Аутентификация: AD/LDAP или локальные пользователи
   - Пул адресов: 192.168.1.210-192.168.1.220

2. IPsec VPN (стандартный клиент):
   - IKEv2 или L2TP/IPsec
   - Сертификаты или Pre-shared key
```

**Настройка за 5 минут:**
```
Веб-интерфейс → VPN → SSL VPN:
1. Включить SSL VPN
2. Указать порт (по умолчанию 443)
3. Выбрать метод аутентификации (Active Directory)
4. Указать пул IP-адресов для клиентов
5. Скачать VPN клиент с Kerio
```

### **2.2 QoS (Quality of Service)**

#### **Приоритизация трафика:**
```yaml
Правила QoS в Kerio:

1. VoIP трафик (высший приоритет):
   Протокол: SIP/RTP
   Порты: 5060, 10000-20000
   Гарантированная полоса: 20%
   Макс. полоса: 30%

2. 1С трафик (высокий приоритет):
   Сервер: 192.168.1.10
   Порты: 1540-1591
   Гарантия: 15%
   Макс: 25%

3. Веб-трафик (низкий приоритет):
   Порты: 80, 443
   Гарантия: 5%
   Макс: 50%

4. Остальной трафик (стандартный):
   Гарантия: 1%
   Макс: 100%
```

#### **Настройка полосы пропускания:**
```bash
# Пример ограничения скорости для отдела
qos rule add name="Sales_Department" \
  source="192.168.1.50-192.168.1.100" \
  guaranteed="10Mbps" \
  max="50Mbps" \
  priority="medium"
```

### **2.3 Фильтрация контента**

#### **Категории фильтрации:**
```yaml
Веб-фильтр Kerio:
1. Блокировка по категориям:
   - Порно (100% блокировка)
   - Насилие (блокировка)
   - Соцсети (разрешить в обед 12:00-13:00)
   - Торренты (блокировка)

2. Блокировка по URL:
   - *.vk.com
   - *.facebook.com (кроме work.facebook.com)
   - rutracker.org

3. Блокировка по ключевым словам:
   - "скачать бесплатно"
   - "взлом"
   - "кряк"
```

#### **График доступа:**
```yaml
Политика доступа:
- Рабочее время (9:00-18:00):
- Обед (12:00-13:00):
- После работы (18:00-9:00):
```

### **3. синхрон времени NTP и траблшут DNS-записей**

### **3.1 Синхронизация времени NTP**

#### **Почему это важно:**
- Kerberos аутентификация в AD требует точного времени (±5 минут)
- Логи с корректными временными метками
- Синхронизация между серверами

#### **Настройка NTP в Kerio:**
```yaml
Веб-интерфейс → Система → Дата и время:

1. Источники времени:
   - pool.ntp.org (основной)
   - time.windows.com (резервный)
   - ntp1.stratum2.ru (локальный)

2. Интервал синхронизации: 60 минут
3. Часовой пояс: Europe/Moscow (UTC+3)
4. Летнее время: Автоматически
```

#### **Настройка NTP сервера в Windows (DC01):**
```powershell
# На DC01
# 1. Указать внешний источник времени
w32tm /config /syncfromflags:manual /manualpeerlist:"pool.ntp.org,time.windows.com" /reliable:yes /update

# 2. Запустить службу времени
net start w32time
sc config w32time start=auto

# 3. Сделать DC NTP сервером для домена
reg add "HKLM\SYSTEM\CurrentControlSet\Services\W32Time\TimeProviders\NtpServer" /v Enabled /t REG_DWORD /d 1 /f

# 4. Настроить клиентов на синхронизацию с DC
# Групповая политика:
# Computer Configuration → Administrative Templates → System → Windows Time Service
```

#### **Иерархия синхронизации:**
```
[Внешние источники]
    ↓
[Kerio Control] → Сервер времени для всей сети
    ↓
[DC01] → Источник времени для домена
    ↓
[Все компьютеры в домене] → Синхронизируются с DC01
```

### **3.2 Траблшутинг DNS-записей**

#### **Типичные проблемы DNS:**
1. **"Сайт не открывается, но ping работает"**
2. **"Не могу найти сервер в домене"**
3. **"Очень медленно открываются сайты"**
4. **"Некорректные IP адреса"**

#### **Инструменты диагностики:**

**A. Командная строка Windows:**
```cmd
# 1. Очистить DNS кэш
ipconfig /flushdns

# 2. Посмотреть DNS кэш
ipconfig /displaydns

# 3. Проверить конкретную запись
nslookup ya.ru
nslookup ya.ru 8.8.8.8  # Через конкретный DNS

# 4. Полная диагностика
nslookup
> server 192.168.1.1    # Переключиться на Kerio DNS
> set type=A            # Искать A-записи
> dc01.lab.local        # Проверить запись
> set type=MX           # Проверить MX записи
> lab.local
```

**B. PowerShell:**
```powershell
# 1. Проверить DNS серверы
Get-DnsClientServerAddress -InterfaceAlias "Ethernet" -AddressFamily IPv4

# 2. Тест разрешения имен
Resolve-DnsName -Name "dc01.lab.local" -Server 192.168.1.1

# 3. Проверить все типы записей
Resolve-DnsName -Name "lab.local" -Type ALL

# 4. Трассировка DNS запроса
Resolve-DnsName -Name "google.com" -Trace

# 5. Проверить обратную зону
Resolve-DnsName -Name "192.168.1.10" -Type PTR
```

**C. В Kerio Control:**
```
1. Проверить DNS Forwarder:
   Веб-интерфейс → DNS → Forwarders
   Должно быть: 8.8.8.8, 1.1.1.1

2. Проверить кэш DNS:
   Статус → DNS Cache
   Очистить если нужно

3. Проверить локальные записи:
   DNS → Hosts
   Пример:
   dc01.lab.local = 192.168.1.10
   srv-sql.lab.local = 192.168.1.20
```
